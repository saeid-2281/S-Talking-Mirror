# S Talking UI Components

## Buttons

Use Primary for the main continuation action, Secondary for ordinary commands, Ghost for low-emphasis actions, Icon-only for obvious toolbar actions with tooltips, and Destructive only after confirmation.

## Inputs

Line edits, combo boxes, spin boxes, sliders, checkboxes, and search fields inherit colors and sizing from semantic theme tokens. Disabled controls must remain readable.

## Data Displays

Tables should keep queue rows dense and readable, with sortable headers, selected-row contrast, concise status badges, and tooltips for elided paths.

Metrics use tabular numbers and compact labels. Empty states should be quiet and actionable.

## Navigation

Menus, context menus, tabs, segmented controls, and the command palette use the same token set and icon family.

## Feedback

Progress bars use Voice Teal. Health, Preflight, provider status, quota meters, notifications, and inline errors must use semantic state colors plus text labels.

## Icon Use

Icons come from `app.gui.icons.ICON_REGISTRY`. Use one stroke style, theme-aware color, and sizes 16, 18, 20, or 24 px. Emoji and mixed icon families are not part of the product UI.
